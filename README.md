# pi-oc2

`pi-oc2` statically analyzes Pi packages and generates native Pi and OpenCode 2 plugins from one portable tool implementation. It does not execute source extensions during analysis, and generated OpenCode 2 code never imports Pi.

The repository currently targets:

- `@earendil-works/pi-coding-agent@0.84.3`
- `@opencode-ai/cli@0.0.0-dev-18204` (`opencode2 v0.0.0-dev-18204`)
- `@opencode-ai/plugin@0.0.0-dev-18204`

## Set up

```bash
git clone https://github.com/tridha643/pi-oc2.git
cd pi-oc2
pnpm install
pnpm build
pnpm verify
```

Run the local CLI with `pnpm pioc -- <command>`. To generate a fixture and invoke its portable tool through both real hosts, run:

```bash
pnpm test:e2e:hosts
```

This uses `@opencode-ai/cli@0.0.0-dev-18204` from the workspace and requires working Pi/OpenCode model credentials.

## Create a new dual-host plugin

```bash
pnpm pioc -- init ./my-plugin
pnpm pioc -- port ./my-plugin \
  --manifest ./my-plugin/pioc.port.json \
  --out ./my-plugin
pnpm pioc -- verify ./my-plugin
```

`init` creates a Pi extension, an Agent Skill, and `portable/hello.ts`. Both generated hosts call that same portable executor.

## Port an existing Pi package

```bash
pnpm pioc -- analyze /path/to/pi-package --out ./analysis
# Read ./analysis/COMPAT.md before writing overrides.

pnpm pioc -- port /path/to/pi-package \
  --manifest ./my-port/pioc.port.json \
  --out ./my-port-output

pnpm pioc -- verify ./my-port-output
```

Every capability is classified as `direct`, `scaffold`, or `unsupported`. `pioc port` and `pioc verify` stop when required behavior lacks a manual implementation or explicit waiver.

Generated packages are self-contained under:

```text
generated/
├── pi/
│   ├── extension.ts
│   ├── portable/
│   └── skills/
└── opencode2/
    ├── server.ts
    ├── tui.ts
    ├── portable/
    └── skills/
```

## Determinism and safety

- Analysis reads JSON, Markdown frontmatter, and TypeScript ASTs. It never imports a source extension.
- Source hashes cover normalized relative paths and file bytes.
- Files, findings, imports, and serialized keys use lexical ordering.
- Repeated generation must produce byte-identical output.
- Generated OpenCode 2 code uses `Plugin.define({ id, setup })`, `ctx.tool.transform`, `ctx.skill.transform`, and a separate TUI `Plugin.define` module.
- Verification checks source/target locks, unresolved capabilities, generated bytes, strict TypeScript, and real `opencode2` config discovery.

See [`docs/design.md`](docs/design.md) for call stacks and [`docs/adr/0001-compile-native-targets.md`](docs/adr/0001-compile-native-targets.md) for the native-codegen decision.
